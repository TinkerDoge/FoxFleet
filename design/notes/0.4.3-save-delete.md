## Why

0.4.3 C2 already landed as **device-only cache delete**. Doge's complaint: trash only drops the phone `.media` file, then tapping the card **redownloads from the hub**. He wants Telegram-like behaviour:

1. **Save** copies the file to a public phone folder so he can open it in other apps (gallery, Files, WhatsApp, etc.).
2. **Delete** (viewer trash) removes it on **the phone AND the hub/bot**, so the next tap cannot fetch it again.
3. Bump the version book to **0.4.3-alpha**, Android **versionCode 39**.

Research (do not vendor Telegram code; copy UX only):

- Telegram-FOSS / official Telegram: viewer **Download** saves to `Pictures/Telegram` (gallery).
- Mercurygram / Goregram: **Delete for everyone** is the default, not "delete for me".
- Telegraher: every media item has **Save to gallery / Save to downloads**.

FoxFleet mapping:

| Telegram | FoxFleet 0.4.3 |
|---|---|
| Save / Download in viewer | Save → MediaStore `Pictures/FoxFleet`, `Movies/FoxFleet`, `Download/FoxFleet` |
| Delete for everyone | Viewer trash → hub revoke + bot blob discard + phone cache |
| Clear cache | Dossier **Clear** and Settings cache clear stay **device-only** |

Do **not** delete the agent's original workspace file on the machine (`MEDIA:/home/...`). Hub forgets the offer; a **new** later reply that tags the same path may offer it again.

## A. Hub — revoke so resolve 404s forever (until a newer message re-offers)

Mentions are in-memory (`server/media.js`). On transcript load, `media.note(...)` is called again (`server/index.js` ~909, ~1116, ~1121). Forgetting only RAM is useless: the next open re-notes and the phone redownloads.

### Persist revocation

Add a durable revoke list on the hub (JSON file next to the registry data, 0600). Shape:

```
{ "v": 1, "rows": [ { "scope": "...", "agent": "...", "ref": "...", "at": 1234567890123 } ] }
```

Load on `mediaHub()` construction. Write atomically (temp + rename).

### `mediaHub` API

- `revoke({ scope, agent, ref, at = now() })`:
  - upsert row
  - drop that ref from `mentioned`
  - drop matching hub byte-cache entries (keys contain the ref)
  - persist
- `revoked(scope, agent, ref) -> at|null`
- `note(scope, agent, text, at = now())`:
  - existing parse
  - if a ref is revoked and `at <= revoked.at`, **do not** re-mention it
  - if a ref is revoked and `at > revoked.at` (a **newer** reply tagged it again), drop the tombstone and mention as usual
- `resolve(...)`: if revoked and no newer mention, throw the same 404 as "never mentioned" (`That file was not offered by this agent`). Never leak that it was deleted vs unknown.
- `knows(...)`: false while revoked without a newer mention.

Pass message `created`/`at` into `note()` from the transcript load sites when the message has a timestamp. Live `note()` on a just-sent reply uses `now()`.

### Bot media

`DELETE` of a `/bot-media/fbm_…/…` ref (see `mediaRef` in `server/bot-media.js`):

1. Parse id with `MEDIA_ID`.
2. `botMedia.discard(reg, botId, store, id)` — already deletes the blob + `store.dropMedia(id)`.
3. Also `media.revoke` so any leftover mention cannot mint a token.

`store.mediaForRef` after discard must be falsy → POST resolve already 404s. Keep that.

Do **not** add a bot websocket op. User-authenticated HTTP only.

### HTTP

`DELETE /api/agents/{name}/media` with JSON `{ "ref": "<exact MEDIA: ref>" }` (same `ref` as POST resolve). Auth = same as POST.

- Connector / native agents: handled in `server/index.js` next to the existing POST `route === 'media'` block (~908).
- Bot agents: handled in `server/bot-api.js` next to POST media (~705). Discard blob if `store.mediaForRef(ref)`, always revoke.

Responses:

- `200` `{ "ok": true, "deleted": true }` when something was revoked and/or discarded.
- `200` `{ "ok": true, "deleted": false }` if already gone (idempotent — phone still drops cache).
- `400` invalid ref (empty / too long), same limits as POST (`maxLength` 2000).
- `401/403` as other agent routes.
- Never 500 on `__proto__` / bad ids.

OpenAPI: add `delete` on `/api/agents/{name}/media` in `contract/openapi.json`. Keep POST unchanged.

Do **not** add a new live event type. Optional: if you already have `message.edited` plumbing and can strip `MEDIA:` lines from **bot-store** messages cheaply, do it; if not, skip stripping. Tombstone + 404 is the acceptance criterion. The Android card may show "Couldn't load this media" / a deleted state; do not redownload.

## B. Android — Save + both-sides Delete

`minSdk` 29. **No new storage permission.** Use MediaStore with `RELATIVE_PATH` (scoped storage). Pattern already in `sideProjects/app/src/main/java/vn/mint/taivideo/DownloadService.kt` — copy the insert/`IS_PENDING` idea, not the downloader.

### Save (new)

Pure helper (easy to unit test), e.g. `android/app/src/main/java/dev/foxfleet/app/media/MediaStoreSaver.kt`:

- Images (`MediaRef.Kind.Image`) → `MediaStore.Images.Media.EXTERNAL_CONTENT_URI`, `RELATIVE_PATH = Environment.DIRECTORY_PICTURES + "/FoxFleet"`

- `DISPLAY_NAME`: `MediaRef.alt` if it looks like a filename, else `foxfleet-<epoch>.<ext>` from mime/kind.
- `MIME_TYPE` from kind (`image/jpeg`, `video/mp4`, …).
- Write from the **leased cache file** (the `.media` on disk), then `IS_PENDING = 0`.
- Return the content `Uri`. Do not scan with the deprecated `MediaScannerConnection` if MediaStore insert is enough.

### Delete (change C2)

Viewer trash is **not** device-only anymore.

1. Confirm dialog (Telegram-ish, one action): title `"Delete this media?"`, body `"It will be removed from this phone and from the hub. Opening it again will not download it."`, buttons Delete / Cancel. Use existing dialog style (`HistorySheet` confirm, `AgentsScreen` confirm).
2. `HubApi`: `DELETE agentPath(agent)+"/media"` with `{ "ref": ref }`. Mirror `resolveMedia` error handling.
3. On 200 **or** 404: then `MediaHost.delete(...)` (local cache). 404 = already gone on hub; still drop the phone file.
4. On other errors: keep the local file, toast the hub error, do not claim deleted.
5. Then `onDelete(current)` so Chat/Dossier drop the item from the swipe list / grid, and close or advance the pager.
6. Button content description: `"Delete for everyone"` (not `"Delete from this device"`).

`HubViewModel.deleteMedia`:

- Make it a suspend that hits the hub then the cache. `MainActivity` currently `onDeleteMedia = { ref -> vm.deleteMedia(...) }` — wire the hub call inside the VM using the same client as `resolveMedia`.
- After success, clear Coil memory cache (already does) and refresh dossier grid if that agent is loaded.

Keep `MediaHost.delete` / `MediaRepository.delete` as the **local** primitive. Dossier **Clear** and any Settings "clear cache" stay local-only (`deleteAgent` / `clear`). Update KDoc that still says "hub copy stays" on the **viewer** path.

`MediaRepositoryTest` `session delete drops the file so the next open downloads again` stays — that tests the **local** primitive. Add a new Android test that `HubApi` builds the DELETE body; do not pretend the repository talks to the hub.

If a card is opened after hub revoke: `resolveWithRetry` currently retries 404 up to 3 times. **Do not retry 404 for a revoked file forever.** 404 after delete should surface `"This media was deleted"` (or keep `"Couldn't load this media"` + Try again is OK if Try again still 404s and does **not** write a new `.media`). Never treat 404 as "download empty".
