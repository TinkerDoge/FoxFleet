## Lane C — Hermes subagent Deepseek v4 pro

**Branch / worktree:** `feat/0.4.3-media-update` at `/home/doge/.hermes/cache/scratch/ff-043-media`

### C1. Durable chat + media cache (no reload every time)

Chat Room cache already exists (`ChatCache` / `CacheDb`, `cacheThenNetwork`). Media lives in `app.cacheDir/media-cache` (`HubViewModel`), which Android may evict.

- Keep media on **durable app-private storage** (`filesDir`, e.g. `filesDir/media-cache`), not `cacheDir`.
- Opening a chat must paint **cached messages immediately** (`Load.Cached`) even offline; network then reconciles. Never blank the transcript while a cache page exists.
- Media thumbnails and the viewer must hit the on-disk file without re-download when the `.media` file is present (`MediaRepositoryTest` already covers warm hits — keep that, add a filesDir persistence test that survives a new `MediaRepository` instance).
- Do not put bytes inside Room JSON.

### C2. Delete media on the device

User can delete a cached media file **locally** (not the hub copy).

- Viewer: a delete/trash action. After delete, the lease is dropped, the `.media` file is removed, next open re-downloads if needed.
- Optional: settings or dossier "clear this agent's cached media".
- Hub messages stay. This is device cache only.
- Add `MediaRepository.delete(identity)` / session-scoped delete; pinned leases still wait until the viewer closes (existing retire semantics).

### C3. Agent card → dossier + media gallery, swipe

`FleetScreen` `AgentRow`: whole row `onClick` opens the chat. Doge: tap the **agent card** to show a dossier / old media; when viewing media, **swipe** to the next.

- Tap **avatar** → dossier. Tap the rest of the row → chat (unchanged). Long-press menu unchanged.
- Dossier (new screen): agent display name, id (small/muted), presence, last chats list (opens that session), **media grid** of image/video refs from cached messages of this agent (all sessions on device).
- Opening a grid item opens `MediaViewer` with the **list**; horizontal swipe (pager) moves between items. Close returns to the dossier.
- In-chat `MediaViewer` should also accept the chat's media list and swipe to siblings (current viewer takes a single `MediaRef`).

### C4. Auto-update APK from DogeDrive

No Play Store. Alphas currently go to Google Drive / Telegram. Doge wants the app to **download the APK from DogeDrive and install**, no manual sideload.

- Settings row: "Check for updates". Also check on cold start (once per 12h, Wi-Fi-prefer, never on metered unless the user taps).
- Manifest JSON (configurable URL, default a constant you introduce — parent will point it at the live DogeDrive/INDC file). Shape:

```json
{ "versionCode": 35, "versionName": "0.4.3-alpha", "apkUrl": "https://...", "sha256": "...", "notes": "optional" }
```

- If `versionCode` > installed, prompt, download to app-private file, verify sha256, then `PackageInstaller` session (`REQUEST_INSTALL_PACKAGES`, Android 10+). Unknown sources already required for sideload; the prompt is the system one.
- Never install if sha256 mismatches. Never run the APK. HTTPS only.
- Do not embed Drive OAuth in the app. The `apkUrl` must be a direct HTTPS download (public Drive/INDC link or hub proxy). If the URL is a Drive view link, document that the parent must publish a direct-download URL; implement the client against a direct file.
- Tests: version compare, sha256 reject, no install when equal/older. Robolectric for the comparer; do not hit the network in unit tests.

**Own:** `MediaRepository.kt` + tests, `MediaViewer.kt`, new dossier composable + navigation from `FleetScreen`/`MainActivity`/`HubViewModel`, cache-open path in `HubViewModel` **only as needed**, `AndroidManifest.xml` (install-packages), new `update/` package, Settings row, tests under `android/app/src/test/...`. No `tokens.json`, no model picker.
